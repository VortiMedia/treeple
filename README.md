Treeple turns a protected area into an interactive grid of symbolic parcels. You
explore a topographic map, pick a square, and reserve it as a conservation gift.
Yellowstone is the first grid; the platform is built to take others.

Reservations are symbolic. They do not convey land ownership.

## Why Treeple

Conservation giving is usually a form and a receipt. Nothing to look at, nothing
to point at, nothing to give.

- A gift has a location, so it can be shown to someone.
- The grid is generated from real coordinates, not decorative.
- The map is the product, so it has to render well before anything else does.
- The platform is area-agnostic; Yellowstone is configuration, not a hard-coded case.

## Quick start

Prerequisites: Node.js 18+, npm, and a free [MapTiler](https://maptiler.com) key.

```sh
git clone https://github.com/VortiMedia/treeple && cd treeple
npm install
cp .env.example .env.local     # add NEXT_PUBLIC_MAPTILER_KEY
npm run dev
```

Open `http://localhost:3000`. Setup problems and their fixes are in
[`docs/SETUP.md`](docs/SETUP.md).

## The grid

| Property | Value |
|---|---|
| Cell size | 1 km × 1 km (247 acres) |
| Tiles | 2,304 covering Yellowstone |
| Coordinates | WGS84 |
| States | available, reserved (14-day hold), sold |

Hover highlights a tile, click opens its detail panel, and pan and zoom work
under touch. Grid generation and the tile schema are in
[`docs/DATA_STRUCTURE.md`](docs/DATA_STRUCTURE.md).

## Stack

Next.js 14 App Router · TypeScript 5 · Tailwind 3 · shadcn/ui · MapLibre GL JS ·
MapTiler · Turf.js. Deployed on Vercel. Phase 1 reads static JSON.

## Current limitations

This is an MVP and the gaps are deliberate, not hidden.

- Reservations are not persisted; there is no backend yet.
- No authentication and no payment processing.
- Grid data is static and regenerated by hand.
- Phase 2 moves storage to Supabase and adds Stripe.
